# 课堂转写原生标点丢失：根因与修复计划

调查日期：2026-09-08。状态：核心代码修复已实施并通过回归验证；原任务数据和导出文件未回写。下方保留根因证据与原计划，实施结果见文末。

## 结论

本次问题发生在后端后处理：共识阶段用去掉大部分标点的词元重建正文，日语标点阶段又把这个结果当作原生标点来源，导致 Qwen 已输出的句读信息无法恢复。忠实稿和智能纠正稿共同继承这一结果。严格单模型模式仍经过共识阶段，因此同样受影响。

## 实际任务证据

- 任务：`d28acd96-5ec4-4e6e-942a-71bdc4bde729`，状态 `completed`。
- 输入：用户提供的 `fb1cce71-cfe5-475e-8890-b48500e20bb9-5c454869-15b5-41c5-8a65-b48500e617ab.mp4`，644.608 秒。
- 对附件计算 SHA-256，与数据库记录完全一致：`dd891e27947ecbd68c44606fb76c02ff27c6af7064850ea98b8e9d011d0c353f`。
- 配置：`ja`、`qwen3_asr_1_7b`、`strict_single`；34 个有效片段、34 个 Qwen 候选。
- 只读查询本地 SQLite 的候选、正文和决策事件；无需重跑模型即可定位丢失阶段。
- 原始稿按 Unicode P 类计数共有 135 个标点：`、` 36、`。` 91、`,` 3、`？` 4、`.` 1。
- 忠实稿和智能稿逐段相同，均剩 29 个 P 类符号，其中仅 1 个 `。`；其他为括号、冒号、点号、连接号，主要来自不可辨识提示及时间码。因此现象准确说是句读标点几乎全部丢失，而非每一种符号都为零。
- 共识策略：31 段 `time_aligned_confusion_network`，3 段 `inaudible_marker`。不可辨识段应继续受质量门控保护，不能为恢复标点而强行采纳原始文本。
- 34 次 `strict_punctuation_applied` 均执行，只有最后一段改变了文本（补 `。`）。来源记录：30 次 `granite_projection`、3 次 `source_fallback`、1 次 `granite_projection+acoustic_boundaries`。来源名不代表实际调用了 Granite。
- 33 个相邻片段的间隔全部为 0 ms，所有片段同为 `SPEAKER_01`。

例：第二段（`bc7e8b79-6752-48fb-acde-8fb0823b1781`）：

```text
原始：では、PowerPoint を共有して授業を進めます。
共识：ではPowerPointを共有して授業を進めます
标点：ではPowerPointを共有して授業を進めます
```

`automatic_consensus_adopted` 事件中已经没有句读标点；之后 `strict_punctuation_applied` 的输入、输出相同。这排除了前端展示才丢标点的解释。

## 代码链路与根因

1. `workers/qwen/adapter.py` 的 `_transcribe()` 获取 `results[0].text` 并返回。实际候选和原始稿证明模型已输出标点。
2. `backend/classscribe/quality/text.py:surface_tokens()` 做 NFKC 归一化，中文、日文分支提取文字与部分字母数字符号，忽略 `、。？` 等句读。作为比较词元合理，但无法完整表达原文表面形式。
3. `backend/classscribe/consensus/alignment.py:_candidate_tokens()` 使用上述词元，`network.py:ConfusionNetwork.resolve()` 经 `_join_tokens()` 重建正文。低支持度的最佳候选回退也经同样重建，不能自然规避此问题。
4. `backend/classscribe/classroom/production.py` 将 `result.text` 同时写入 `faithful_text` 和 `smart_corrected_text`；术语阶段随后只处理智能稿，无法恢复已经丢失的句读。
5. 同文件 `_punctuation()` 的日语分支传入 `granite_proposal=faithful_source` / `smart_source`，实际是无标点的共识结果，未提供 Qwen 原始候选。日语函数对自身比较距离为零，即使提取到零个边界，也记录 `granite_projection`，掩盖了无效恢复。
6. `_acoustic_boundaries()` 只看片段尾部与下一片段的间隔，不看片段内部静音。本例片段连续、说话人一致，不满足 250/700 ms 阈值；末段无后继，硬编码 700 ms，故只在末段补一个句号。
7. `frontend/src/pages/TranscriptPage.tsx:segmentText()` 直接返回对应数据库字段，未执行去标点操作。

根本设计缺口：用于共识比较的词元与用于展示的表面文本没有分离，也没有将候选中的原生标点作为独立边界证据传递到后处理。

中文、英文共用共识链路，也存在丢失原生句读的风险。中文 FireRedPunc 可能重建部分标点；英文目前也把处理后的正文传给 `native_text`。这两种语言的用户任务未在本次实测，需纳入回归验证。

## 修复顺序

### 1. 先建立会失败的回归用例

- 用无时间戳、带句读的 Qwen 风格日语候选，覆盖严格单模型的共识→术语→标点→持久化链路；相邻片段间隔为零、无额外标点模型。
- 断言上面的真实短句能保留逗号和句号；覆盖 `？`、`！`、引号、括号、混合英文、空格及全半角字符。
- 同时覆盖最佳候选回退、原生带时间戳词元、无有效候选占位提示、多候选不一致、术语替换使文字长度变化的情况。

### 2. 建立原生标点证据传递，优先修复单候选场景

- 保留现有词元投票及其质量门控、时间戳和来源信息；单独携带原始候选的表面文本、标点边界、候选 ID 和模型 ID。
- 对通过质量门控、且与最终文字序列可精确对应的候选，将原生标点映射回输出。单候选、文字未变的情况应能无损保留句读；空格保留单独定义并测试。
- 不直接修改公共 `surface_tokens()` 让标点参与所有质量比较，不直接把整个 `raw_text` 覆盖为忠实稿；这两种做法会改变评分或绕过已生效的质量、术语决策。
- 对多候选拼接及文字差异，用字符/词元对齐和最终选择来源映射边界。仅投影有可靠对应关系的边界，歧义处保守回退。
- 不沿用日语 `_project_granite_boundaries()` 的按总长度比例缩放来处理文字增删；这种方法会把标点移入错误词语。
- 使用显式的原文偏移映射处理 NFKC 差异。标点阶段仍严格保持输入的非标点字符序列，不借机改变全半角、大小写或术语。

### 3. 接通生产路由与两层文本

- 将 `granite_proposal` 抽象为模型无关的原生边界提案，生产路由传入实际被采纳候选的证据；覆盖中、日、英原生标点优先路径。
- 忠实稿基于最终共识正文恢复；智能稿使用术语编辑的偏移映射，将相同证据投影到自己的正文，分别校验字符不变性。
- 保持现有术语→标点的检查点顺序也可实现上述方案，避免无必要的流水线迁移。
- 候选不可靠、字符无法对齐或目标为不可辨识提示时，不恢复候选内容。额外模型/声学证据仅作为明确的补充路径；本次 Qwen 日语修复无需新增模型依赖。
- 声学增强作为后续独立改进：利用真实 VAD/静音边界映射段内停顿，不以连续切片边界推断段内无停顿，不对每个切片强制补句号。

### 4. 修复可观测性并验证导出

- 来源应记录真实模型、候选 ID、提取/采用的边界数、拒绝原因和回退原因。零个投影边界不能记为有效 `granite_projection`。
- 更新规则版本。对“可靠原生候选存在句读，但恢复后全部丢失”的情况记录可诊断事件；避免对正常短句统一报警。
- 验证 API、忠实/智能稿显示、JSON/Markdown/SRT/VTT 导出，确保之后的对齐与验证阶段不再覆盖标点。

### 5. 恢复已完成任务

- 先在数据库一致性备份/隔离副本上，用已保存的候选和决策证据重放修复后的后处理，无需再次进行 Qwen ASR 推理。
- 为当前任务生成逐段前后差异：字符正文、标点、不可辨识提示、人工编辑和导出变化分别核对。
- 提供可重复执行、带规则版本与审计事件的任务级重处理方式；保留 `raw_text`、`user_text`、人工决策及原有审计记录，保留旧导出版本。
- 使依赖最终文本的对齐、验证、导出检查点正确失效并重建；不得只更新数据库正文而留下过期导出。
- 本次调查不执行旧任务写入。实施时先完成预览与回滚路径，再应用到选定任务。

## 实施结果

- 新增 `backend/classscribe/consensus/punctuation.py`，在共识正文生成后恢复原生表面文本/标点。正常共识与最佳候选回退共用该实现。
- 仅使用通过质量门控且实际选中词元的来源候选。单一来源且非标点字符完全相同时保留原始表面形式（包含空格）；否则只在匹配文字块和相邻词元来源一致的边界投影。NFKC 只用于匹配，不修改最终字符；短小/重复且有歧义的差异块不投影。
- 恢复在术语纠正之前完成，因而智能稿的术语增删自然保留外围标点，无需增加术语偏移重映射。词元投票、时间轴和质量门控不变。
- 共识审计新增 `punctuation_sources`（候选 ID、模型 ID、边界数），共识规则升级 v2。日语生产路由不再把正文冒充 Granite 提案；原生标点记录为 `native`，零边界不再记录有效 Granite 投影。中文优先保留现有原生句读；标点结果规则升级 v2，worker RPC 合同不变。
- 新增回归覆盖：日/中/英原生表面文本、原生时间戳、低支持度回退、无效候选、候选切换、全半角映射，以及实际生产的共识→术语→标点→数据库审计链路；检查人工编辑不变、术语长度变化、零片段间隔和重复标点处理幂等。
- 验证：共识/术语标点/生产审计相关 37 项测试通过；对齐导出/共识持久化/完整媒体到自动导出/批量复核相关 19 项测试通过。另已通过生产 runner 与 ASR 持久化相关检查。Ruff、修改范围的 Mypy（18 个文件）和 `git diff --check` 通过。
- 一次额外扩展到通用课堂调度测试的运行长时间未结束，已终止；没有将其计为通过。随后单独运行上述直接相关的完整生产与导出测试，19 项全部通过。
- 对实际任务做只读预览：固定原有正常/不可辨识决策，用已保存候选重建正常段落，不重跑 ASR。31 个正常段落恢复，3 个不可辨识段落不变，全部 34 段通过非标点字符不变性检查。正常段落按 `、。！？,.` 统计由 2 个恢复到 122 个句读符号。预览文件：`/tmp/classscribe-punctuation-preview.json`。
