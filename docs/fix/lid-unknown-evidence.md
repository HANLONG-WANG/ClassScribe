# LID 非语音窗口导致任务中断

原实现对整段录音按 5 秒窗口执行语言分类，包括 VAD 未检测到语音的窗口。FireRedLID 是多语言分类器，可能对噪声输出 zh/ja/en 之外的标签。原 worker 把这些正常分类结果当作内部错误，课堂 runner 又丢失具体原因，最终仅记录 `WORKER_CRASH: RuntimeError`。

## 修复

- VAD 无语音覆盖的窗口不调用 LID，保留零证据观察和跳过原因。
- worker 对不支持的分类返回成功响应、`language=null`、`language_status=unknown`，并保留原始语言与置信度。非法数值、格式异常及实际执行失败仍然报错。
- 路由保留中、日、英原始概率；未知证据不触发切换，低于既有 0.8 阈值的结果不建立或切换语言。仍要求连续可靠窗口支持正常切换。
- 没有任何可靠语言证据时报告 `LANGUAGE_UNDETERMINED`，不因零概率并列而默认中文。无语音与不可靠窗口也不会稀释有效证据的平均置信度。
- 听写端将未知分类视为缺少辅助证据，避免压低主模型的有效判断，且不会从全零或弱证据中选择高精度模型语言。
- 真实 LID 调用失败保存 `LID_FAILED`、窗口编号、时间范围与 worker 具体说明。检查点保留经过凭据/路径脱敏并限长的错误信息。

## 验证

原失败窗口为 22.5-27.5 秒：VAD 无语音覆盖，原始分类为 `pa`、置信度 0.243。修复后的独立 worker 正常返回未知结果；课堂路径直接跳过该窗口。

对原 644.608 秒录音的完整 LID 阶段验证通过：257 个窗口，15 个无语音窗口、3 个不支持语言的结果，其余为可靠分类，最终路由为日语。验证的数据库改动回滚，原任务状态不变。

FireRed worker 源码修改后需通过 `WorkerEnvironmentProvisioner.ensure("firered")` 生成对应源码指纹的环境。本机已使用离线依赖缓存完成，不改变模型权重或锁定依赖版本。重启服务后，新调用会使用修复版本。
