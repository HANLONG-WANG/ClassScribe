# 课堂模型会话复用与分轮调度

## 生命周期

课堂执行器在 `run_until_blocked` 期间持有任务租约。模型工作进程由独立、稳定的异步事件循环管理，跨检查点的 `asyncio.run` 不会销毁它。未持有租约的调用保留一次调用后卸载的行为。

课堂所有模型（包括 FireRed VAD/LID）共用一个 GPU 通道，切换时先卸载旧模型，再加载新模型。VAD/LID 在检测到 NVIDIA 计算设备时明确请求 CUDA，加载失败不会静默回退 CPU；无 GPU 环境保留自动设备选择。输入法的 VAD/LID 仍显式使用 CPU 常驻，不受课堂设备路由影响。模型切换、任务暂停/取消/完成、进程故障或服务关闭时释放相应会话。IBus 请求 GPU 时，课堂 GPU 推理需到达安全边界并完成实际释放；清理期间收到的继续或重试请求会保留，不会被重复任务去重吞掉。

复用身份包含任务、模型 ID/固定版本、工作环境以及音频文件身份。同一模型跨任务也不共享进程状态。音频替换、工作环境或活动版本变化会使会话失效。GPU 等待队列中的任务在获得资源后再次检查暂停/取消状态，避免启动已取消的请求。

模型选择只检查安装元数据；每次真正加载仍完整校验模型文件。同一次驻留会话内不重复读取全部权重，未引入跨会话的长期校验缓存。模型 RPC 失败后销毁进程，重试重新校验和加载。

## 调度与恢复

- 正文保持原有片段顺序，同模型连续片段复用会话。
- 自动复核分为第二模型、第三模型、最终共识三轮。前两轮按模型分组；各片段分别提交检查点和候选结果。复核模型路由固定在对应主候选上，后续轮次只能使用匹配主候选与版本的结果。
- 旧任务恢复时会为尚未完成的复核补充分轮检查点，已完成的结果保持不变。无需数据库结构迁移。
- 结构分析先完成全部 MOSS 窗口，再连续执行说话人模型，仍按原时间顺序做说话人关联、去重和最终分段。
- 结构窗口、语言窗口及细分复核音频块的成功响应原子保存到任务目录；暂停或进程重启后按请求、版本、环境和音频身份恢复。失败响应不缓存。
- 窗口安全边界的暂停不消耗模型失败重试次数。正常关闭服务留下可恢复的 pending 检查点，而不是错误标记为 IBus 暂停。
- 最后一个检查点处理期间收到取消请求，也不会误写成任务完成。

界面新增“复用已加载模型”“模型已保留”“恢复已完成窗口的结果”和分轮复核说明；每个片段仍独立保存，不是合成一个无法暂停的巨大请求。

## 验证

测试覆盖跨事件循环复用、模型版本失效、任务隔离、失败销毁和重新加载、课堂 VAD/LID 与其他模型共用 GPU 串行执行、输入法辅助模型保持 CPU、等待 GPU 时取消、IBus 等待真实释放、清理期间重试、服务关闭恢复、结构结果恢复和复核结果一致性。

本机 RTX 4070、已安装 Qwen 1.7B 的合成短音频验证：同一进程连续执行三次识别，首次含校验/加载约 12.803 秒，后两次约 0.121 / 0.123 秒，文本一致，结束后进程与会话正常释放。这不是长音频整体吞吐量基准；首轮还包含运行库初始化和编译开销。


2026-09-08 课堂 VAD/LID GPU 路由回归：58 项相关测试通过，Ruff、改动文件严格类型检查及架构检查通过。RTX 4070 上使用已安装固定权重，通过当前源码适配器分别验证 CUDA 和 CPU 加载、推理、卸载与工作进程退出。5.765 秒合成英语音频单次推理：VAD GPU 0.078 秒 / CPU 0.017 秒，LID GPU 0.320 秒 / CPU 1.077 秒（不含加载；CPU 2 线程）。这只是短音频冒烟检查，不代表长课堂吞吐量或完整输入法延迟；短帧 VAD 不保证 GPU 更快。LID 保持 float32，CUDA 加载后 PyTorch 已分配显存约 3477 MiB；生产切换仍须等待工作进程退出以释放其 CUDA 上下文。未修改输入法 CPU 常驻策略。
