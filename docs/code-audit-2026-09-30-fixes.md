## 补充建议的处理

- 配置写入口只接受当前生效组；保留期限有严格后端验证与实际维护任务，未支持的音频落盘明确拒绝。启动器、core 与 doctor 共用实际配置来源。
- 全局检查点按身份复用并拒绝参数冲突，初始化/补检查点串行事务；词条 upsert 用 immediate transaction 和逐条 flush，批内重复和并发不增加重复身份。
- 数据库、导出/文件 hash、材料解析和诊断等阻塞 HTTP 操作进入线程池；请求体有 64 MiB 上限，较大录音使用原有流式上传。
- SSE broker 每任务及全局留存均有界，删除任务清理缓存；序列在换代/淘汰后仍单调。
- IBus engine 销毁移除 timer；长稿件列表及时间轴窗口化，选中段保持可见。
- 浏览器存储统一容错；请求、上传、下载有取消/超时/可见错误；词条语言迁移改为单个原子请求。
- 已计算 PCM channel metrics 复用；rolling context 的结构字段与 rendered 共用预算；gold 标注时长按音频区间并集统计，重叠/重复不虚增覆盖。
- 维护与全量清除互斥，活动基准/听写不清除；清除后停止未来维护。退出等待维护实际线程，维护错误重试，所有资源独立清理。
- 质量与共识审计规则升级 v3，基准评分合同升级 benchmark-quality-v2。旧评分不能直接用于新自动排名，应重新跑基准。
- 既有格式门错误已修复，16 个纯格式文件前后 AST 一致；未更改系统工具、用户数据、模型权重或既有 tmp 音频实验。

## 使用和验证边界

worker/protocol 源码改动会令原有冻结运行环境显示 source_changed。实际推理前请使用现有“修复运行环境”操作重建；本次没有隐式联网修改用户已安装环境。没有可靠词时间时，系统保留证据并明确要求复核，不能宣称自动解决声学上无法证明的边界。
